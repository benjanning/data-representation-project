# Reservation workspace: explain the decision without duplicating the rules

The overview previously answered how many vehicles were available but left the user to identify them in another flow. The availability disclosure now calls the existing availability rule and shows actual confirmed overlapping periods using the same exclusive-return overlap predicate. Available actions preselect vehicle and the current period in the existing form. No booking, price or allocation rule is reimplemented in this view, and confirmation still rechecks availability and price inside the relevant storage transaction.

Reservation search reads saved snapshots rather than joining current customer/vehicle display values. Status filtering is applied first, then all search words must match the snapshot text. Search and clear submit explicitly, preserving keyboard focus. A successful creation clears old filters/search so the new record is visible and returns focus to the stable workspace; existing hash navigation uses the same focus region.

The CSV contains exactly the shown records in their shown order, including terminal history. Fields: rental ID, persisted status, vehicle reference/model, customer name, UTC collection date, exclusive UTC return date, days, daily-rate cents and saved-total cents. Dates and quoted amounts retain the saved values. UTF-8/BOM supports common spreadsheet import; quoted cells preserve commas, quotation marks and line breaks. Free text starting with formula-like characters (including after whitespace) receives an apostrophe prefix. Quoted values are historical examples, not revenue or payment records. The report reflects the displayed snapshot, not a new live transactional database query.

Three new Node checks independently parse exports with Python's CSV reader, reconcile exact cents/dates/status and exercise search, punctuation, Unicode, multiline text and formula-like input. Two new browser journeys run against the actual Flask and static frontends, verifying blocked/free vehicles, an adjacent-period handover, preselection, quotation/confirmation, exact downloaded rows, combined status/search, empty export, cancellation releasing allocation, keyboard focus and 390px layouts. The original nine journeys and domain/MySQL integration checks remain in the same workflow.

The public site remains browser-local synthetic data; this change adds no server deployment, payment, real customer data or cross-device allocation capability. All original CRUD, quote/idempotency/concurrency rules and coursework remain intact.
